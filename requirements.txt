# Installed AFTER routertl (README: `pip install routertl`, then
# `pip install -r requirements.txt`). Every line is a floor or a range, never an
# exact `==` pin: an exact pin on a package routertl's own dependencies already
# installed at a newer version DOWNGRADES it (pytest, pluggy, packaging,
# markdown-it-py, ...), measured on a clean machine with routertl 5.5.0 (DS-P2.337).
# The floors are the versions this tree was tested with. Packages that only come in
# as another package's dependency are not listed: their parent's resolver owns them.
# tools/tests/test_requirements_no_downgrade_ds_p2_337.py refuses a new `==` line, and
# CI runs tools/ci/requirements_no_downgrade.py after the install.

# DS-P2.109: track the routertl floor (routertl pyproject `cocotb>=2.1`,
# RTL-P3.1682) instead of pinning ==2.0.1. Both gates share ONE interpreter's
# site-packages, so a `==` pin against a moving floor made them downgrade/
# upgrade cocotb in turn and break each other. RTL-T1.37 fixed the direct-sim
# "No GPI_USERS" regression that the 2.1 floor exposed. `<3` matches pyuvm's
# own cocotb ceiling. tools/cocotb_dependency_floor.py guards this invariant.
cocotb>=2.1,<3
cocotb-bus>=0.3.0
# DS-P1.86: track routertl's own cocotb-test requirement (>=0.3 since
# RTL-P1.194); a ==0.2.6 pin made `pip install -r` beside routertl

# refuses any pin here that excludes a routertl requirement.
